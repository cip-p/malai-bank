# Kensa e2e reports are published into the website bucket under /end-to-end-flows

The backend pipeline publishes the Kensa report generated by a green end-to-end run on main directly into this site's static-website bucket, under the `/end-to-end-flows/` prefix. The prefix names what a visitor sees — end-to-end scenario flows with sequence diagrams — rather than the tool that generated them; "Kensa" would mean nothing to a visitor as a URL. The report is a self-contained static viewer (an `index.html` plus a JS bundle that fetches JSON data files at runtime), so it serves from the existing bucket and edge distribution with no new infrastructure and is browsable at `/end-to-end-flows/` on the site domain. The architecture page links to it as live [[Kensa]] evidence.

## Considered options

- **Commit the report into this repo's `public/`.** Couples the two repos on every backend pipeline run, adds ~4.4 MB of generated churn per commit, and puts the report's internal service vocabulary inside `src/**`-adjacent content where the forbidden-terms lint operates.
- **A dedicated evidence bucket and subdomain.** Cleanest isolation, but new IaC (bucket, distribution, certificate, DNS) for content that a prefix serves equally well at demo scale.
- **Same bucket under `/end-to-end-flows/` (chosen).** Zero infrastructure changes: the backend CI deploy role already holds the object-write and cache-invalidation permissions, and the edge URI-rewrite function serves prefixed static trees as-is.

## Consequences

- The site deploy's orphan sweep (`ci.sh`, phase 2 `--delete`) excludes `end-to-end-flows/*`, exactly as it excludes `_astro/*`. Removing that exclusion deletes the published report on the next site deploy.
- Ownership of the prefix lives with the backend pipeline: it syncs with `--delete` scoped to `/end-to-end-flows/`, injects a `<base href="/end-to-end-flows/">` tag so the slash-less `/end-to-end-flows` URL resolves (the edge rewrite serves `index.html` without redirecting), and invalidates `/end-to-end-flows/*` after upload.
- The report never enters this repo's build: it is absent from `src/**`, the sitemap, and therefore the forbidden-terms lint and sitemap-crawl gates. This is deliberate — the report names internal modules as part of its evidentiary value, and that vocabulary remains banned in authored site copy.
- The path `/end-to-end-flows` is reserved: adding an Astro page at `src/pages/end-to-end-flows.astro` would collide with the published tree in the bucket.
- Renaming the prefix means changing both repos in lockstep: the backend's publish action and the sweep exclusion here name it literally, and objects under the old prefix linger in the bucket until removed by hand.
- Locally and on a fresh environment the `/end-to-end-flows/` link 404s until the backend pipeline has published once; `tests/e2e/end-to-end-flows.spec.ts` covers the report only when `MALAI_WEBSITE_URL` points at a deployed environment.
