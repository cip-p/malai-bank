# 01 — MDR client pair records Model Decisions

Status: done
Category: enhancement

## What to build

First slice of `.scratch/payment-screening/PRD.md`. The MDR gains its client-module pair so other services can record Model Decisions: `malai-mdr-client` (production) and `malai-mdr-client-test-support` (WireMock stubs + builders), following the established client-pair pattern. The client exposes the record-model-decision call against the MDR's internal write endpoint — service JWT bearer, client-minted entry id as the natural idempotency key, request shape matching the internal contract (correlation, model identity, prompt-template pin, rendered prompt, retrieved-context refs, outcome with its cross-field rules, verdict, latency, cost). The actionable-output read is NOT in this slice (issue 05 adds it).

Both modules register in the root build (modules and dependency management — a module declared only in dependency management won't build), and the client's base-url property joins the shared client-test defaults so the pair's own tests boot. Base-url propagation into consuming services belongs to the consumer slices, not this one.

- [x] Response deserialisation covers the created response (entry id, decision id, seq, outcome)
- [x] The test-support module offers a With-style stub interface and request/response builders in the house TestBuilder style
- [x] Both modules registered in the root build; the base-url property added to the shared client-test defaults
- [x] `mvn install` green
