# 04 — Type the retrieved-context refs in the MDR contract

Status: done
Category: enhancement

## What to build

Hand-back from the webapp's three-surfaces work (`malai-webapp/.scratch/three-surfaces/PRD.md`). The Decision replay read serves `retrievedContext` as an array of untyped objects (`additionalProperties: true`). The Ops surface's Decision view is required to present retrieved-context refs with their content hashes — provenance is the point of the field per the MDR CONTEXT.md ("refs point at mutable rows in other contexts and are detection, not recovery") — but the contract doesn't promise the keys the UI must render, so the frontend currently renders defensively against an unpromised shape.

Type the context-ref item in `openapi.yaml` (at minimum: the Correlation-style type and id halves, and the content hash) and align the serialised shape, so the generated client gives the webapp a real type and Zod validation instead of a bag.

## Agent Brief

**Category:** enhancement
**Summary:** Type the retrieved-context ref items in the MDR replay contract and re-impose that shape on the read path.

**Current behavior:**
The Decision replay read (`GET /api/v1/admin/mdr/decisions/{decisionId}`) serves `retrievedContext` on the Model Decision view as a nullable array of untyped objects (`items: {type: object, additionalProperties: true}`). The Kotlin read model carries `List<Map<String, Any?>>?`: refs are persisted as JSONB and deserialised back as raw maps, so the typed write-side shape never reaches the response schema, and the webapp renders defensively.

**Desired behavior:**
The contract types the context-ref item as a named, closed object with three required string fields — `type`, `id`, `contentHash` (the Correlation-style ref halves plus the content hash; per the MDR CONTEXT.md, refs are provenance — detection, not recovery). The replay read serialises exactly that shape: the read path re-imposes the typed ref (reuse the write model's `RetrievedContextRef` or a read-side equivalent) instead of passing raw maps through. Absent/null `retrievedContext` behaviour is unchanged. Existing seeded decisions (one seeded ref today, type `AUTHORISATION_HISTORY`) replay without loss.

**Key interfaces:**
- The OpenAPI item schema for `retrievedContext` on the Model Decision view schema — becomes a named object schema, three required string fields, closed to extra properties
- `RetrievedContextRef` — the authoritative field set on the MDR write model
- The MDR entry row-mapping and read service that currently deserialise the `retrieved_context` JSONB as `List<Map<String, Any?>>`
