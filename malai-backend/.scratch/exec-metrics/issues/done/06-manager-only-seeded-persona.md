# 06 — A manager-only persona, so the narrow role is provable

Status: ready-for-human
Category: enhancement

## What to build

Per ADR-0010: without this, `MANAGER` is decorative. The demo evaluator holds every hat, so `MANAGER` and `ADMIN` are observationally identical to them — nothing on any screen demonstrates that the narrow role is narrow. A seeded persona holding only `manager` is what makes the boundary real, and the admin API's refusal is the proof.

Seed a demo identity in the `manager` Cognito group **only**, with no customer estate at all — mirroring `CustomerOnlySeed` exactly: pinned UUIDs continuing the existing scheme, its own deterministic seed so the dataset reproduces byte-for-byte per reset, the same dev-only permanent-password posture, and a surgical clean. Exclusion from the demo all-hats grant must be structural — no `admin` or `customer` group-add call exists for this identity anywhere — rather than a conditional that could later be inverted.

Because the persona has no account-holder context, it inherits the 403/`4999` degrade path that three-surfaces issue 06 shipped for holder-scoped endpoints. No new contract work is needed there; confirm it holds rather than building anything.

Credentials must be reachable by the webapp's Playwright suite, following the same pattern as the existing personas: documented env overrides that work today, plus the named secret for CI.

## Acceptance criteria

- [x] Seed creates a `manager`-group-only identity with no customer estate, idempotently; clean removes it surgically
