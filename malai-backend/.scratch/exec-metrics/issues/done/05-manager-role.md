# 05 — `MANAGER`, the narrow executive role

Status: ready-for-human
Category: enhancement

## What to build

Per ADR-0010. The platform gains a fourth **Role**, `MANAGER`, which Offers the Exec surface and nothing else — so a bank can give its CFO the dashboard without also handing over the power to rule on decisions that move money. `ADMIN` remains the superset and keeps Exec.

`MalaiRole` gains the `manager` → `ROLE_MANAGER` mapping — the single point where Cognito groups become authorities. The metrics endpoint re-gates from `hasRole('ADMIN')` to `hasAnyRole('MANAGER','ADMIN')`. `RegistrationOrchestrator`'s `demoAllRoles` branch grants `manager` alongside `customer` and `admin`, so the demo evaluator keeps every hat and the scripted journey needs no edits. The property stays default-off: a real-bank deployer must never inherit a policy that hands every registered user an executive dashboard.

**The contract change is deliberate and needs conscious approval, not a workaround.** Adding `MANAGER` to the `roles` enum on `/api/v1/user` widens a *response* enum — the same shape that made the payment-state widening trip the compatibility check during payment screening. Approve it consciously, note the approval in the resolution, and do not reshape the contract to dodge the check.

Depends on the `manager` Cognito group existing in the environment — a `malai-infra` hand-off, tracked below. The backend code can land before the group is applied; nothing resolves the role until a token carries the group.
