# AML case terminal transitions are Gate-governed

An AML case's terminal transitions needed the same enforcement discipline as referred payments, and we decided both closes consult the MDR at the moment of the officer's action — generalising ADR-0009 beyond payments: model output moves the bank only through the Gate, whatever the resource being moved. Close-as-reported reads the SAR decision's actionable output synchronously: an accept or edit ruling in force yields the (possibly edited) narrative, which is attached as the case lands `CLOSED_REPORTED`; no ruling, or a reject in force, is a domain-coded 409 refusal that leaves the case `INVESTIGATING` — conservative-only, per ADR-0008. Close-as-dismissed is the mirror guard: refused while any linked alert's ruling in force is an accept, so a case with confirmed suspicion cannot be closed as noise. Unlike payments there is no resolver sweep — a referred payment waits unattended for its ruling, so payments-service polls the gate; a case close is a human-present action, so the read happens once, synchronously, and a refusal is the officer's answer, not a retry queue's.

## Considered Options

- **Resolver-sweep polling (the payments shape)** — a scheduled job watches ruled SAR decisions and closes cases once actionable. Rejected: it inverts the workflow. The officer's close is the action being governed, not an outcome awaiting delivery; a sweep would close cases nobody asked to close.
- **aml-service reads Human Dispositions directly** — rejected for the reason ADR-0009 recorded: the accept/edit/reject → actionable-output translation lives in the Gate alone, and no consumer re-derives what "actionable" means.
- **Ungoverned close (trust the officer)** — the officer accepted the draft, so attach whatever the latest draft said. Rejected: the case must carry the ruled artifact, provably the one the human saw — the edit ruling makes the difference concrete, since the attached narrative must be the edited output, not the model's.
