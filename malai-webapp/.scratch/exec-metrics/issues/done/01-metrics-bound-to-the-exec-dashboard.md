# 01 — Real numbers on the Exec dashboard

Status: ready-for-agent
Category: enhancement

## What to build

Webapp side of `malai-backend/.scratch/exec-metrics/PRD.md`. The four **Metric tile**s stop rendering the "metrics API pending" caption and start rendering the bank's actual figures.

Refresh the checked-in OpenAPI snapshot and regenerate the client — the generated client stays the only way this app talks to the API. A dedicated hook consumes `GET /api/v1/exec/metrics` and translates the contract's per-metric availability into first-class tile states, so `UNAVAILABLE` becomes the honest em-dash the tile already knows how to draw rather than a loading artefact or a caught error. The distinction matters: a tile showing an em-dash because the source is down and a tile showing one because the page is still loading are different facts and must not look identical.

The tiles bind without layout rework — they were shaped for this. Money metrics render with the currency the contract supplies, never an assumed one. The fourth tile is labelled **Payments stopped**; "fraud prevented" appears nowhere in copy.

The dashboard renders `asOf` so it states its own freshness, and gains an explicit refresh control. A visible refresh reads as more trustworthy in a demo than a number that changes on its own — the presenter acts, presses refresh, and the audience watches the figure move. This one query opts into `refetchOnWindowFocus`; do not flip the app-wide default, which was set deliberately. Mount-refetch already works, so navigating from Banking to `/exec` refetches with the existing zero `staleTime` — no new machinery for the main demo path.

No polling. A `refetchInterval` makes numbers drift mid-sentence, adds e2e flakiness, and raises a live-region question the a11y spec would have to answer.

Until the backend's later slices land, three of the four metrics legitimately return `UNAVAILABLE` — the page must look correct and deliberate in that state, not broken.
