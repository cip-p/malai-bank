# 03 — The manager-only gating proof

Status: ready-for-agent
Category: enhancement

## What to build

The test that makes `MANAGER` real rather than decorative. The demo evaluator holds every hat, so nothing they see distinguishes the narrow role from `ADMIN`; only a session holding `manager` alone can demonstrate the boundary, and the API's refusal is the actual proof.

A Playwright journey signing in as the seeded manager-only persona: they land on `/exec` and the dashboard renders; Banking and Ops routes render the **Access page**; and the admin MDR API refuses them. Follow the existing customer-only gating spec as prior art — it makes the same argument for the other end of the role model — including a second setup project writing its own storage state, and allow-listing the expected 403s in the API-failure guard fixture so the proof does not read as an incidental failure.

The persona signs in via the direct Cognito path in test setup, exactly like the existing staff personas; the passwordless posture is unchanged.
