# CLAUDE.md (malai-webapp)

Greenfield React app for malai. **`src/` is empty** — every pattern (folder layout, state shape, component split, data-fetching conventions) is decided as we build. Treat early decisions as proposals; refine via `/grill-with-docs` and `/improve-codebase-architecture` before they ossify.

Cross-module invariants (OpenAPI contract authority, auth flow, no-comments rule, audit / idempotency conventions) live in the root `CLAUDE.md`, one level up. Inherit and extend; don't restate.

## API client (already wired)

Generated by `@hey-api/openapi-ts` into `src/api/generated/`. Configured plugins:

- `@hey-api/client-fetch` — fetch-based runtime client
- `@tanstack/react-query` with `queryOptions` + `mutationOptions` — typed Query/Mutation factories
- `zod` with `requests: true, responses: true` — runtime validation of payloads

**Source of truth**: the contract is the hand-authored `malai-backend/malai-api/src/main/resources/static/openapi.yaml`. This repo keeps a checked-in **snapshot** at `./openapi.yaml` (~57KB) — that snapshot is what `openapi:gen` reads by default. Refresh it from the backend whenever the contract changes: copy `../malai-backend/malai-api/src/main/resources/static/openapi.yaml` over it. Nothing checks automatically that the two copies match.

**Workflow when the contract changes**:

1. Backend edits `openapi.yaml` (the source of truth) and lands the change.
2. Refresh this repo's `./openapi.yaml` snapshot.
3. `npm run openapi:gen` (also runs automatically before `build`).
4. TypeScript errors guide you to the call sites that need updating.

**`npm run openapi:verify` guards step 3** (runs in CI's `build` job). It regenerates from the committed snapshot and fails if the committed client differs, catching hand-edited generated code and forgotten regens. `prebuild` regenerates before every build, so without this check CI would silently rewrite the client and build green over a mismatch.

**Step 4's guarantee has a hole worth knowing about.** TypeScript only guides you to call sites that access the contract _typed_. A stringly-typed lookup (`obj[key]`, `key in obj`, an `any`/`unknown` bag) opts out, and a renamed field then fails silently at runtime instead of loudly at compile time. That is exactly how the `hash` → `contentHash` rename blanked every content hash on the Ops Decision view while the build stayed green. Read contract fields as `ref.contentHash`, not `refField(ref, "contentHash")`.

## Backend communication

- Direct HTTP to `VITE_API_BASE_URL` (no `/api` proxy through the Vite dev server). The choice is deliberate — proxying would make browser↔Vite same-origin and suppress CORS preflight, hiding real CORS misconfiguration until production. With direct calls, dev mirrors deployed behaviour. See `vite.config.ts`.
- **Auth is cookie-based**: backend sets HttpOnly `access_token` + `refresh_token` cookies on login. Fetch calls must include credentials (`credentials: 'include'`) so cookies travel with API calls. The cookie-vs-header decision is owned by the backend; see the root `CLAUDE.md`.
- **When the API isn't there at all, the app pauses itself.** `BackendAvailabilityGate` (wrapping `<App/>` in `main.tsx`) runs a **readiness probe** — `GET /ready`, public, six-second timeout — and while it fails the whole router is replaced by `ServicePausedPage`. The probe is the only authority on the question; other calls failing in an unreachable-looking way (`NetworkError`, or `502`/`503`/`504` — see `isBackendUnreachable`) only cause it to be re-asked. It polls itself back to life, so a returning backend needs no reload. See ADR-0023. **Consequence for local dev**: with no local `malai-api` running you now get the paused page instead of a permanent "Loading…" — that is the mechanism working, not a regression.

## Testing

- **Unit / integration** — Vitest 4 + `@testing-library/react` + `@testing-library/user-event` + jsdom. Setup file: `src/test/setup.ts`. `npm test` runs it once; CI runs it on every change.
- **No browser-level suite.** The Playwright e2e suite was removed: it signed users in against real AWS Cognito, which nothing here can reach any more. Behaviour that needs a real backend is checked by hand against a local `malai-api` (see README).
- **Passwordless flows** — register / login / verify are covered at unit/integration level (`LoginPage.test.tsx`, `RegisterPage.test.tsx`, `VerifyPage.test.tsx`).
- **An unhandled error fails the run.** `dangerouslyIgnoreUnhandledErrors` used to be on repo-wide, to tolerate an `input-otp` <= 1.4.2 timer leak that threw `ReferenceError: window is not defined` after jsdom teardown on slow runners — green tests, `Errors 1 error`, exit 0. That is fixed upstream in 1.5.0 and the option is gone. If a third-party teardown race shows up again, fix or contain it where it happens (upgrade, drain that file's timers, or fake timers); don't re-suppress it for the whole suite. See ADR-0024.

Testing is the first-class concern in this repo. Match patterns when they exist; when you're inventing the pattern, write the test first (`/tdd`) and grill the design (`/grill-with-docs`) before the second occurrence.
